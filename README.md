# Decision Diff 2

Многопользовательское приложение для сравнения двух срезов ответов СПР. Отдельные серверные страницы, загрузка ресурсов, права доступа, подтверждение пользователей, версии и история действий. Базовый стек сохранён: Python, SQLite, HTML/CSS/JavaScript без внешних Python-зависимостей. Для выполнения пользовательского кода добавлен Docker.

## Первый запуск

Нужны Python 3.10+ и Docker с поддержкой Linux-контейнеров. На Windows подойдёт Docker Desktop, включённый в режиме Linux containers. На Linux Docker daemon должен быть запущен и доступен пользователю, запускающему сервер.

Распакуйте архив в новую папку. **Не заменяйте файлы внутри старой установки:** формат хранилища изменился. Старая версия и её результаты останутся отдельно. Автоматической миграции пользователей/запусков версии 1 нет.

Откройте терминал в папке `decision_diff_v2`.

1. Создайте первого администратора и импортируйте открытый датасет/выданные проверки:

```bash
python app.py --create-admin admin --import-demo
```

На Linux при необходимости используйте `python3` вместо `python`. Команда спросит отображаемое имя и пароль дважды. **Готовых паролей нет**. Пароль — от 8 символов. Администратор создаётся только этой локальной командой, обычная регистрация не выдаёт административных прав.

2. Соберите контейнерный образ (при первой сборке нужен интернет для базового образа):

```bash
docker build -t decision-diff-runner:2 -f Dockerfile.runner .
```

3. Запустите веб-сервер:

```bash
python app.py
```

4. Откройте http://127.0.0.1:8765 и войдите под созданным администратором. Выберите «Демонстрационный прогон» → «Новое выполнение».

В Windows можно воспользоваться `setup_windows.bat` для первого шага, затем `build_runner_windows.bat` и `start_windows.bat`.

Без Docker можно пользоваться страницами, регистрацией, загрузкой ресурсов и правами. **Расчёт будет отклонён с понятной ошибкой. Незаметного запуска Python на веб-сервере нет.**

## Сброс забытого пароля

Остановите веб-сервер (Ctrl+C), откройте терминал в папке существующей установки и выполните:

```bash
python app.py --reset-password admin
```

Вместо admin укажите фактический логин. Введите новый пароль дважды; ввод скрыт. Старый пароль не нужен. Данные, права и результаты сохраняются, прежние сессии этого пользователя закрываются. Команда доступна только через консоль сервера. Если используется DD_STATE, укажите тот же каталог хранения. Затем снова запустите `python app.py`.

## Пользователи

Регистрация создаёт учётную запись в состоянии `pending`. До подтверждения доступна только страница состояния. Администратор открывает «Администрирование», подтверждает заявку. Пользователь входит заново: старые сессии при изменении статуса отзываются.

Администратор также может отклонить или заблокировать участника. Проверка статуса происходит при каждом запросе; блокировка действует и для сохранённых ссылок. Для хакатонной команды отображаемое имя используется как подпись автора, логин — для входа. Это учётная подпись, не электронная цифровая подпись.

## Страницы и навигация

- `/runs` — список доступных прогонов.
- `/runs/new` — создание прогона из конфигурации.
- `/runs/<id>` — настройки, история выполнений, кнопка запуска.
- `/runs/<id>/edit` — изменение настроек через формы выбора ресурсов.
- `/datasets` и `/datasets/new` — список и загрузка датасетов.
- `/datasets/<id>` — карточка и загрузка следующей версии.
- `/scripts` и `/scripts/new` — процедуры/метрики и редактор с загрузкой `.py`.
- `/scripts/<id>` — код (при наличии прав), описание и редактирование.
- `/configurations` — конфигурации обработки; отдельные страницы создания и редактирования.
- `/resources/<id>/access` — настройка доступа.
- `/resources/<id>/history` — версии и журнал действий с авторами.
- `/executions/<id>` — обзор конкретного выполнения, прогресс и журнал.
- `/executions/<id>/pivot` — сводная с изменяемой группировкой.
- `/executions/<id>/checks` — результаты проверок и экспорт HTML.
- `/executions/<id>/applications` — список заявок выбранной группы.
- `/executions/<id>/applications/<app>` — сравнение заявки.
- `/admin` — подтверждение пользователей и готовность Docker runner.

Это обычные серверные страницы, а не SPA. Фильтры/группировка/пагинация хранятся в URL. Работают обновление страницы, ссылки, новые вкладки и кнопки браузера «Назад/Вперёд». JavaScript нужен только для прогресса, описаний скриптов, извлечения docstring и удобств редактора. Основные формы работают и без него.

## Ресурсы и права

Одинаковая модель применяется к датасетам, скриптам, конфигурациям и прогонам:

- **Личный:** только владелец и администраторы.
- **Поимённый:** указанные пользователи, каждый со своей ролью.
- **Общий:** все подтверждённые пользователи, с общей ролью reader/editor. Индивидуальное назначение может повысить роль.

| Роль | Просмотр | Использование в своём прогоне | Редактирование | Запуск прогона | Управление доступом |
|---|---|---|---|---|---|
| Читатель | Да | Да, если есть права на все выбранные входы | Нет | Нет | Нет |
| Редактор | Да | Да | Да | Да | Нет |
| Владелец | Да | Да | Да | Да | Да |
| Администратор | Все ресурсы | Да | Да | Да | Да |

Запускающий должен быть редактором/владельцем прогона и иметь хотя бы чтение всех используемых датасетов/скриптов. Редактирование общего скрипта для его использования не требуется.

Прямое скачивание исходных датасетов и скриптов для читателей задаётся отдельно: общая галочка или индивидуальное разрешение. Редакторы/владельцы могут скачивать исходники. Сам просмотр результатов прогона не выдаёт прав на скачивание входов и чтение исходного кода процедур. Правила проверяются сервером, включая прямые ссылки и старые версии.

**Существенная граница:** читатель ресурса может использовать его при создании своего прогона; владелец такого прогона имеет право писать и выполнять собственный Python над этими входами. Этот код видит входы целиком и способен включить их в результат. Поэтому запрет кнопки скачивания не является DRM или запретом извлечения данных через вычисления. Не выдавайте доступ к использованию датасета человеку, которому нельзя доверять его содержимое. Это явно отражено на странице настройки доступа.

Доступ к результатам можно предоставлять отдельно: читатель прогона видит отчёты и данные заявок, даже если исходный датасет ему не открыт. Отзыв доступа к прогону закрывает и URL всех его выполнений. Уже скачанный HTML отозвать нельзя.

## Датасеты

Загрузка: ZIP до 64 МБ, распакованный объём до 256 МБ, до 50 000 записей, один JSON не больше 4 МБ. Структура:

```text
RESULTS/
  BEFORE_MASTER/I1001.json
  AFTER_BETA/I1001.json
```

Разрешена внешняя папка перед RESULTS. Файлы вне RESULTS игнорируются, опасные пути и ссылки отклоняются. В обоих срезах должен быть хотя бы один файл, идентификаторы могут не полностью совпадать. JSON должен быть объектом. Имена заявок: латиница, цифры, дефис и подчёркивание.

Загрузка следующего архива через карточку создаёт новую версию датасета. Предыдущие версии и их содержимое сохраняются.

## Скрипты и описания

Для скрипта задаются русское название, описание и назначение: нормализация, сравнение, агрегация, проверка/метрика. Название и описание показываются в форме выбора скриптов.

Можно загрузить `.py` с компьютера или вставить код в редактор. Редактор работает локально, без CDN: подсветка Python, номера строк, Tab/Shift+Tab для одной или нескольких строк, автоматический отступ при Enter, удаление отступа по Backspace и сохранение по Ctrl/Cmd+S. Escape снимает фокус, чтобы выйти из области кода клавиатурой.

Если сервер обнаружил ошибку синтаксиса, отсутствие нужной функции или конфликт версий, он возвращает ту же форму с исходным кодом и заполненными полями, HTTP 422. Не нужно нажимать «Назад», чтобы исправить ошибку.

Черновик дополнительно автоматически сохраняется в sessionStorage текущей вкладки отдельно для пользователя и страницы. Он переживает обновление и возврат на страницу; удаляется автоматически только после подтверждённого сервером сохранения. Если сохранённая версия ресурса изменилась, редактор предлагает явно применить старый черновик к новой версии. Закрытие вкладки/очистка данных браузера может удалить такой черновик — это не серверное хранение и не синхронизация между устройствами. Можно скачать текущий буфер кнопкой «Скачать код .py».

Тип «Проверка / метрика» по умолчанию требует `run(mart, params=None)` и контракт CHECK. Сам по себе произвольный `print(...)` не является подключаемой проверкой. Для остальных назначений нужны функции, указанные в подсказке над редактором. Кнопка «Вставить шаблон» создаёт рабочий пример проверки или заготовку соответствующей процедуры.

Извлечение названия/описания из docstring не требует наличия run: это отдельная операция чтения метаданных. Кнопка «Заполнить из docstring» берёт первую строку начального блока документации как название, остальные — как описание:

```python
"""Проверка снижения одобрений

Отмечает продукты, у которых доля одобренных заявок снизилась.
"""
```

На сервере используется `ast.parse`/`ast.get_docstring`, код для извлечения метаданных **не исполняется**. Если название/описание пусты при сохранении, они также заполняются из docstring. Сохранение проверяет синтаксис и наличие функций контракта. Полная проверка поведения выполняется внутри контейнера.

Каждое сохранение создаёт версию. Если другой участник уже изменил ресурс, сервер откажется затереть его изменения и предложит обновить страницу. Старый код можно открыть через историю. Новый файл не меняет уже выполненные расчёты.

Контракты унаследованы от первой версии:

```python
# Нормализатор
normalize(document, app_id, source, params) -> list[dict]
segments(before, after, app_id, params) -> dict
# Сравнение
compare(union_rows, params) -> Iterable[dict]
# Агрегация
aggregate(rows, segments, params) -> Iterable[dict]
# Проверка / метрика
run(mart, params) -> list[dict]
CHECK = {"id": "custom", "label": "Название", "params": {}, "entrypoint": run}
```

Схемы таблиц и MartAPI — в `docs/` и исходных процедурах. `normalize.py` содержит правила ключей всех массивов. RAW хранит канонический JSON скаляра, поэтому NULL, строка `"NULL"`, false, 0 и отсутствие поля различаются. Сначала строится вертикальный normalized с SOURCE, затем сравнение, разрезы и facts. Исходные пять проверок не изменены.

Для нескольких продуктов одинаковая целевая модель/порог/причина хранится одним значением, разные значения — JSON-картой product_id → значение; PRODUCT_DETAILS сохраняет полные сведения по продуктам. Эту трактовку стоит согласовать с организаторами.

Параметры конфигурации: `normalize_params`, `compare_params`, `aggregate_params`, `check_params`. В `check_params` ключ — ID ресурса проверки (виден в URL её карточки), значение — параметры этой проверки. При запуске имена автоматически сопоставляются с файлами внутри контейнера.

## Прогоны, выполнения, история

При создании прогона настройки конфигурации копируются в него. Изменение исходной конфигурации не меняет прогон автоматически. Настройки самого прогона редактируются на отдельной странице.

Каждый запуск создаёт **новое выполнение**. В нём фиксируются версия настроек прогона, точные версии датасета и скриптов, SHA-256 загруженных файлов, точный ID контейнерного образа и параметры. Используются последние версии доступных ресурсов на момент запуска, затем их копии неизменны. Предыдущий результат не перезаписывается. Повторный расчёт с новой проверкой — новое выполнение, не изменение старого.

История хранит создание, изменения до/после, изменения прав и запуск/завершение расчётов. В каждой записи — автор, отображаемое имя, дата и детали. Автор берётся из сессии, подставить его из формы нельзя. Версии и аудит защищены SQL-триггерами от UPDATE/DELETE. Это защита на уровне приложения/SQLite, не внешняя криптографическая система аудита; администратор файлового сервера управляет самой БД.

## Контейнерный исполнитель

На каждое выполнение создаётся отдельный Linux-контейнер. В него монтируются только:

- выбранная версия датасета, только для чтения;
- зафиксированные копии скриптов и параметры, только для чтения;
- отдельная рабочая папка результатов этого выполнения, с правом записи.

Контейнер не получает базу пользователей, сессии, файлы других выполнений, каталоги ресурсов, Docker socket или переменные окружения сервера.

Настройки запуска: UID/GID 65534, read-only root filesystem, network none, cap-drop ALL, no-new-privileges, память 1 ГБ, CPU 2, до 64 процессов, ограниченный /tmp, до 10 минут. Одновременно допускается два расчёта. Консольный вывод сохраняется до 1 МБ, но поток продолжает вычитываться. Объём файлов результатов проверяется периодически; это не жёсткая файловая квота. При превышении лимита/таймауте контейнер удаляется, выполнение получает failed. Ограничения ресурсов требуют соответствующей поддержки cgroups в Docker-хосте.

После остановки контейнера в каталог отчёта копируются только ожидаемые обычные файлы. Символические ссылки не принимаются. Сервер открывает SQLite только из этого отдельного каталога, в read-only/query-only режиме. Длительность SQL-запросов и объём facts дополнительно ограничены.

Docker-контейнер — практическая изоляция для прототипа, **не гарантия защиты от целенаправленных атак на ядро**. Для публичного исполнения враждебного кода нужен отдельный worker-хост/VM, жёсткие дисковые квоты и дополнительный аудит. На сервере команды также не стоит публиковать встроенный HTTP-сервер напрямую в интернет: для внешнего доступа нужен HTTPS reverse proxy.

Документация используемых опций:
- https://docs.docker.com/engine/containers/run/
- https://docs.docker.com/engine/containers/resource_constraints/

Дополнительные Python-пакеты устанавливает администратор при сборке образа. Интернет во время выполнения отключён. Другой заранее собранный образ можно задать переменной `DD_RUNNER_IMAGE`. Самостоятельной установки пакетов участниками нет.

## Хранение и эксплуатация

- `state/app.sqlite` — пользователи, сессии, ресурсы, права, версии, аудит, список выполнений.
- `state/objects/` — загруженные версии датасетов и кода.
- `state/executions/<id>/input/` — зафиксированные входные процедуры и config.json.
- `state/executions/<id>/artifacts/` — готовая витрина, summary.json, checks.json и журнал.
- `state/executions/<id>/console.log` — ограниченный консольный вывод.

Полный отчёт открытого датасета занимает около 370 МБ, во время обработки и копирования необходимо больше места: предусмотрите не менее 2 ГБ свободного места на расчёт. Удаление ресурсов и сборка старых версий из интерфейса пока не реализованы: это позволяет не потерять связанные результаты.

Параметры сервера:

```bash
python app.py --host 127.0.0.1 --port 8765
```

`DD_STATE` задаёт другой каталог хранения. `DD_TIMEOUT` — таймаут worker в секундах, по умолчанию 600. Docker build-контекст исключает всё, кроме engine.py и Dockerfile.runner: данные и пользователи не попадают в образ.

Перезапуск страницы не влияет на расчёт. При перезапуске самого сервера незавершённые контейнеры удаляются, выполнения помечаются failed, история сохраняется. Можно создать новое выполнение.

## Проверка

```bash
python -m unittest discover -s tests -v
```

Выполняются тесты сравнения, прав, регистрации/подтверждения/блокировки, CSRF, загрузки файлов, docstring без исполнения кода, версий, конфликта правок, истории, отзывов доступа и отдельных HTTP-страниц.

Один интеграционный тест обрабатывает **доверенные выданные процедуры** напрямую в тестовой среде и проверяет отчёты всего датасета. Это специальная тестовая фикстура; сервер не предоставляет такого режима исполнения.

Реальная проверка контейнера включается отдельно после сборки образа:

Linux:
```bash
DD_TEST_DOCKER=1 python -m unittest discover -s tests -p test_docker_runtime.py -v
```

PowerShell:
```powershell
$env:DD_TEST_DOCKER="1"
python -m unittest discover -s tests -p test_docker_runtime.py -v
```

## Границы готовности этой версии

- В среде разработки Docker отсутствует. Построение команды и отказ без контейнера проверены автоматически, **реальный запуск Docker здесь не проверен**. Для него включён отдельный тест выше.
- Визуальная проверка в настоящем браузере в этой среде не выполнена. HTTP-навигация/формы/отчёты проверены автоматически, JavaScript проверен на синтаксис; алгоритмы отступов, выделений, автоотступа и безопасной подсветки дополнительно проверяются командой `node tests/test_editor.js` (Node нужен только для этого теста, не для приложения). Перед защитой нужен проход в Firefox/Chrome на машине команды.
