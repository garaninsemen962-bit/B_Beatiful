## Gemini: потоковое получение и диагностика обрыва

После изменения клиента полный набор: **53 теста, 52 успешно, 1 Docker-тест пропущен**. Добавлены 12 профильных проверок в `test_gemini_client.py`:

- сборка структурированного JSON из SSE-фрагментов, исключение thought-текста, финальное событие usage;
- CRLF, комментарии/heartbeat, многострочные data-события и последняя строка без пустого разделителя;
- режим single для сравнения и low thinking по умолчанию для Gemini 3, без этого параметра для Gemini 2.5;
- отказ при EOF/[DONE] без STOP, MAX_TOKENS, повреждённом JSON и блокировке;
- RemoteDisconnected до HTTP-заголовков, IncompleteRead внутри ответа, отдельные ошибки DNS, TLS и тайм-аута;
- подробности HTTP-ошибки с удалением ключей и URL, отсутствие текста модели в логах;
- лимиты размера и проверка настроек до сетевого запроса;
- настоящий локальный HTTP/1.1-сервер с chunked SSE (границы 7 байт проходят внутри UTF-8 и JSON) и сервер, принимающий запрос, но закрывающий соединение без ответа; подтверждено отсутствие автоматических повторов.

Регрессии AI-страницы, кеша, ACL и экранирования также прошли. Схема БД и Docker runner этим патчем не менялись. Реальный Google API не вызывался; причиной конкретного пользовательского обрыва тесты не являются. Следующий запуск с `python3 gemini_client.py --check` на пользовательской машине должен проверить получение ответа новым клиентом и показать этап возможного сбоя.
