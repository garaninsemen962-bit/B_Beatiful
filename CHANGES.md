# Дополнение: обработка неполных пар, промпты и root

## Обновление: качество входных данных, личные промпты и root

Остановите сервер и сохраните резервную копию вашего `state` (либо каталога `DD_STATE`). Замените файлы проекта из папки `decision_diff_v2`, сохранив существующее хранилище. Скопируйте **весь проект**, включая новые `ai_prompts.py`, `root_admin.py`, `web/prompts.js`, `web/root.js` и `checks/check_parse_errors.py`. Дополнительные Python/npm-пакеты не нужны. При первом запуске схема SQLite обновится автоматически; перед изменением непустой старой БД создаётся снимок в `state/backups`.

**Обязательно пересоберите Docker runner:** обработка входных JSON выполняется внутри него.

```bash
docker build -t decision-diff-runner:2 -f Dockerfile.runner .
python3 app.py --host 0.0.0.0
```

Команды выполняются из каталога проекта. Если используете собственный `DD_RUNNER_IMAGE`, пересоберите соответствующий образ и сохраните прежнюю настройку. Обновите вкладки браузера через Ctrl+F5. Уже полученные результаты остаются прежними: для исправленной фильтрации нужен **новый полный расчёт**. Запуск только новых проверок по старой витрине не восстановит сведения о повреждённых ответах.

### Отсутствующие и повреждённые ответы

Загрузка ZIP сохраняет исходные файлы, в том числе повреждённые JSON, и показывает предупреждение. Можно загрузить датасет, в котором целиком отсутствует один срез: расчёт завершится отчётом качества и пустой сводной. Архив без единого JSON отклоняется; ограничения размера, путей и повторов файлов сохраняются.

Перед сравнением проверяются оба ответа каждой заявки. Отсутствующий файл, невалидный UTF-8, пустой/повреждённый JSON, повтор ключа, NaN/Infinity или верхний уровень не в виде объекта получают отдельный статус. UTF-8 с BOM поддерживается. Ошибки данных при нормализации также фиксируются отдельно по срезам. Процедура может добавить `validate(doc, app_id, source, params)`: возврат `False` отклоняет ответ. Общие ошибки разрезов или сравнения пары записываются отдельно. Неожиданная программная ошибка скрипта по-прежнему завершает расчёт с ошибкой.

Если любой ответ отсутствует или отклонён, **вся пара** исключается из нормализованной витрины, comparison, facts и бизнес-проверок. Настоящие `ATTRIBUTE_NEW` и `ATTRIBUTE_LOST` внутри двух корректных ответов продолжают определяться: пропускать все односторонние атрибуты в `compare.py` было бы ошибкой.

Обзор выполнения показывает входные, сопоставимые и исключённые заявки. Ссылка открывает отдельный список исключений; карточка показывает статусы BEFORE/AFTER и причины. Причины можно скачать в `input_errors.json`; технический `parse_errors.log` содержит строки `BEFORE:APP_ID` / `AFTER:APP_ID`. Общие ошибки пары находятся в JSON и витрине. Отчёты доступны по тем же правам, что и выполнение.

В каждом новом отчёте автоматически добавляются обязательные проверки «Ошибки исполнения BEFORE/AFTER» с числителем по каждому срезу и знаменателем по объединению входных идентификаторов. Примеры ведут к карточкам исключений. При отсутствии сопоставимых пар появляется отдельный FAIL с LOW confidence: нулевые показатели бизнес-проверок не означают успешный анализ. Новая `check_parse_errors.py` позволяет загрузить дополнительную пользовательскую проверку качества через интерфейс; она использует MartAPI, поэтому работает и при повторных проверках без доступа к исходным JSON. По умолчанию не импортируется, чтобы не дублировать обязательные строки.

В старой витрине без новых таблиц качество помечается как неизвестное; PASS задним числом не создаётся. Повторные проверки новой витрины сохраняют сведения о качестве и не изменяют исходную витрину. В сводке Gemini различаются знаменатели входных и сопоставимых заявок; идентификаторы исключений во внешнюю сводку не передаются.

### Личный системный промпт Gemini

В «Мой профиль» есть свёрнутый блок дополнительных настроек. Сохранённый там текст используется по умолчанию только для новых анализов этого пользователя. На странице Gemini свёрнутый блок позволяет выбрать личный текст, встроенный текст или собственный промпт для текущей отправки. Правку для одной отправки можно сохранить как личную настройку. Лимит — 16000 символов; сохранение или сброс настройки не отправляют запрос Google.

Каждый анализ сохраняет фактически использованный текст, источник и SHA-256. Поздняя правка профиля не меняет выполняющийся запрос или историю; промпт входит в ключ кеша. Читатели прогона могут раскрыть промпт, использованный в его анализе. Личные настройки других пользователей не доступны через интерфейс/API; как и другие серверные данные, они доступны оператору root. Формат JSON и ограничения ссылок E1… задаются отдельным техническим контрактом приложения. Старые записи без снимка явно показывают, что исторический промпт неизвестен.

### Удаление пользователей

В администрировании появились удаление и список удалённых пользователей. Удаление закрывает вход и отзывает сессии, сохраняя авторство, ресурсы и историю. Логин остаётся занят. Восстановленная учётная запись сначала заблокирована: администратор должен отдельно разрешить вход. Это удаление учётной записи из действующей системы, а не физическое стирание её истории и ресурсов.

Нельзя удалить себя, защищённый root, последнего активного администратора или пользователя с незавершённым расчётом/Gemini. Отдельные ресурсы по-прежнему удаляются через свою корзину.

### Консоль сервера root

Root создаётся/перенастраивается **локально**, с заданием нового пароля не короче 12 символов:

```bash
python3 app.py --create-root
python3 app.py --host 0.0.0.0 --enable-root-console
```

Прежний `DD_STATE` должен оставаться тем же. Если запись `root` уже существовала, локальная команда сохраняет её ID, сбрасывает пароль и отзывает сессии. Переименование обычного пользователя или галочка администратора не дают серверных прав. Обычная регистрация логина root запрещена. Консоль выключена без флага `--enable-root-console`.

Войдите как `root`, откройте пункт «Сервер root» и повторно подтвердите пароль. Доступ к операциям действует 15 минут и может быть закрыт кнопкой. Неверные пароли root ограничены пятью попытками с адреса за пять минут.

Возможности:

- файловый менеджер по доступным серверу путям: переходы, скачивание, загрузка, редактирование UTF-8, создание каталогов, перемещение и удаление в `state/root-trash`;
- резервная копия перед заменой/редактированием файла в `state/root-backups`, контроль конфликта при сохранении текста; редактор — до 2 МБ, загрузка — до 64 МБ;
- поиск SQLite в хранилище, ручной путь к другой SQLite, просмотр схемы и таблиц, один SQL-запрос; чтение по умолчанию, изменение по отдельному флажку с резервной копией выбранной базы; результат до 200 строк / 2 МБ, для следующих страниц используйте LIMIT/OFFSET;
- командная строка с рабочим каталогом, выводом stdout/stderr и остановкой процесса; до двух команд одновременно, лимит 1–300 секунд и 1 МБ вывода. Команды выполняются без интерактивного ввода; временная история хранится в памяти 30 минут. Для других СУБД доступны установленные на сервере консольные клиенты.

**Root приложения выполняет команды с правами пользователя ОС, запустившего сервер. Повышения до системного UID 0 нет.** Команды имеют доступ к окружению процесса, включая настроенные ключи. Это полный административный доступ в пределах этих прав: изменения файлов, SQL и команды могут нарушить работу приложения. Пользовательские процедуры и метрики остальных пользователей продолжают запускаться в Docker.

Консоль следует открывать через HTTPS, приватный VPN или SSH-туннель; пароль нельзя передавать через публичный HTTP. Для локального туннеля сервер можно оставить на `127.0.0.1`. В аудите сохраняются факты операций и хеши SQL/команд; сами команды, вывод и личный текст промпта в аудит не записываются. Копии и корзина занимают место и очищаются оператором.

Проверки этого выпуска и ограничения среды описаны в [tests/VALIDATION.md](tests/VALIDATION.md).

## Дополнение: диагностика RemoteDisconnected

Gemini-клиент вынесен в gemini_client.py. По умолчанию используется потоковый SSE с low thinking для Gemini 3; собирается только полный валидный JSON. Это исправление недостатков клиента, а не подтверждённое устранение конкретного обрыва на пользовательском подключении. Для обновления нужны два файла: ai_review.py и gemini_client.py; Docker runner для этого дополнения не пересобирается.
